# 阿里云 RDS 网络观测补充核查：VPC 流日志、NIS、镜像与云防火墙

核查日期：2026-10-27。范围：现有普通 RDS for MySQL 实例，通过云侧网络产品独立得到公网或内网双向字节量的可行性。本文仅核查官方公开文档，未开通付费服务、创建流日志、修改业务路由或访问业务数据库。

## 结论

1. **可行的间接方案是从全部业务客户端的弹性网卡侧采集 VPC 流日志，按 RDS 私网地址和数据库端口统计双向 bytes。** 这首先得到“已覆盖客户端与该 RDS 之间的私网网络流量”，只有验证所有私网访问路径均被覆盖后，才可称为该 RDS 的完整业务内网流量。[1][2]
2. **尚未找到能据以承诺“给 RDS 所在 VPC/交换机开启流日志，就直接得到 RDS 托管网络端的全部公网和内网流量”的官方说明。** VPC 流日志文档描述 ENI/VSwitch/VPC 三种采集粒度，未明确说明普通 RDS 托管侧网络接口受支持。创建接口还列有 `OperationFailed.EniTypeNotSupport` 错误。不能仅因 RDS 位于该 VPC 就推断服务端已被采集。[1][2]
3. NIS 商业版流量分析器使用 VPC/TR 流日志作为数据源，**不会增加底层采集范围**；它可用于分析已经采到的数据，不能凭 RDS 公网 IP 直接创建不存在的流量计数。[3]
4. 流量镜像明确不支持将**托管弹性网卡**作为镜像源或镜像目的。可以研究客户端 ECS 侧镜像，但不能据此承诺直接镜像普通 RDS 的托管侧网卡。[4][5]
5. 云防火墙当前互联网边界支持资产清单未列普通 RDS 原生公网端点；因此**没有确认到它可直接采集现有 RDS 原生公网 IP 全量双向流量的官方依据**。若访问 RDS 的全部客户端本身都经已保护的 ECS/EIP/NAT 边界，防火墙可记录经过这些边界的对应流量；覆盖范围仍是这些客户端/网关经过的路径。[6][7][8]

## VPC 流日志能够提供什么

官方说明流日志“采集并记录弹性网卡的进出流量信息”，支持弹性网卡、交换机、VPC 三种粒度；选择 VPC/交换机时采集其关联弹性网卡，包括后续新增网卡。[1]

日志字段包括 `eni-id`、`srcaddr`、`dstaddr`、`srcport`、`dstport`、`protocol`、`direction`、`bytes`、`packets`、`start`、`end`、`action` 和 `log-status`。`direction=in/out` 以被采集网卡为方向基准；`bytes` 为字节数。[1]

可选窗口为 1、5、10 分钟，默认 10 分钟。这里文档称“采样间隔”，但说明的行为是把窗口中的五元组流量聚合成日志，不能自行解释为按固定比例抽取数据包。`TrafficPath=all` 在创建 API 中被解释为“全量采集”。同时 `log-status=SKIPDATA` 明确表示可能因系统过载跳过流日志记录，不能把缺失记录无条件当作零。[1][2]

### 在客户端侧统计 RDS 私网流量

前提是已识别实际业务使用的 RDS 私网端点/IP、实际端口和客户端 ENI，包含只读/代理端点、切换后的地址与跨 VPC、专线等访问来源。需要跟踪 DNS 解析和 IP 变更，按流量发生时间使用正确的地址集合。按单侧客户端 ENI 计数，避免同时统计流量路径两端或多个重复采集点。

| RDS 方向 | 客户端 ENI 日志筛选方式 | 计算值 |
| --- | --- | --- |
| RDS 内网入站 | 客户端 `direction=out`，目的 IP 为 RDS 私网 IP，目的端口为实例实际数据库端口 | 相应窗口 `sum(bytes)` |
| RDS 内网出站 | 客户端 `direction=in`，源 IP 为 RDS 私网 IP，源端口为实例实际数据库端口 | 相应窗口 `sum(bytes)` |

以 `ACCEPT` 业务流量作为基线，同时检查 `log-status` 和采集覆盖状态；正常数据标记 `OK`，`SKIPDATA`、未就绪、采集/查询失败及尚未确认覆盖的窗口标记为不完整或缺失，不能填零。`NODATA` 也需要结合采集状态确认含义。聚合字节量除以完整窗口秒数得到平均 B/s；乘 8 可转为 bit/s。官方示例也使用 `sum(bytes*8/60)` 计算一分钟窗口带宽。[1]

这是一种网络层观测方案，不能直接保证与 RDS 引擎监控指标的统计层次、协议开销和窗口完全相同。若进一步用“RDS 总量 - 客户端侧内网量”估算公网，需要先对齐单位、时间窗、方向、节点/代理范围并核验口径，否则相减可能包含未覆盖客户端、重传、协议开销或其他流量差异，不能标为精确公网量。

### 适用限制与费用

- 当前官方文档没有明确确认普通 RDS 托管侧接口的流日志支持范围；需通过既有日志样本、只读 ENI 发现，或向阿里云提交具体实例/网络架构工单确认。`DescribeNetworkInterfaces` 的 `ServiceManaged`、`Description` 可以识别可见的托管 ENI，但“查不到”不能证明 RDS 没有服务侧接口。[2][5]
- 单个应用 ECS 的采集结果只覆盖该 ECS，不能从整台 RDS 的总流量中直接扣除并称为剩余公网流量。跨账号、外部 IDC、其他云、数据库代理和新增加的客户端均需检查覆盖。
- VPC 流日志需要开通功能和日志服务；官方创建流程使用 `AliyunVPCLogArchiveRole`/`AliyunVPCLogArchiveRolePolicy` 向 SLS 投递。应用只需查询已经采集的数据，不需要新增业务数据库账号。[1]
- 生成费按日志量计费，每个主账号每地域每月 5 GB 免费额度，首档为 2.5 元/GB；SLS 写入、存储和查询等另按其计费规则收费。接入 NIS 还会增加流量处理与存储费用。免费额度不是全部链路免费。[1][3]
- 只有开启后的数据可用；阿里云 VPC 默认不记录网络日志。此前未开通的数据不能靠补充查询权限追溯还原。[1]

## NIS 与流量镜像

NIS 流量分析器官方工作原理明确：“日志采集能力由数据源对应的产品提供，流量分析器本身不直接负责流日志的采集。”当前支持 VPC 流日志、TR 流日志，经过聚合富化后提供 IP/协议/拓扑等分析。杭州支持接入，但这不等于 RDS 服务端原生流量有新的直接采集通道。[3]

流量镜像支持复制指定 ENI 的 IPv4 出入流量，并通过 VXLAN 发送到路由可达的分析目的。官方限制包括：[4]

- 托管 ENI 不能作为镜像源或目的。
- 只支持同账号、同地域，支持同/跨 VPC。
- 镜像流量占用实例带宽；带宽达到上限时丢弃镜像流量，优先保障业务。
- MTU、报文截断和源 ECS TSO/UFO 行为会影响接收的镜像报文，不可把镜像接收端的接口总字节数当成 RDS 业务流量。
- 实例费为 0.1 元/镜像源/小时，另有流量处理费；当前文档写明 2027-03-31 前免流量处理费。另需分析目的的计算和存储资源。

因此，针对只需分钟级流量趋势的目标，应先考虑客户端 ENI 流日志；流量镜像需要更多运维资源，且同样不能解决未覆盖的客户端路径。

## 云防火墙

互联网边界官方支持的 IPv4 资产清单包括 ECS 公网 IP/EIP、ENI EIP、NAT、CLB/ALB/NLB、GA 等，未列普通 RDS 原生公网端点。其流量日志的必要条件是相关资产已经开启保护，并且流量实际经过该防火墙；未受保护的资产不会被记录。[6]

官方日志审计说明，流量日志记录经过云防火墙的网络流量详情，包含源/目的 IP、端口、协议及流量大小；默认可查询最近 7 天，导出原始日志或延长存储需开通日志分析。[7]

主动外联分析支持按被保护的公网资产和 NAT 后的客户端私网 IP 查看流量、外联目的 IP 和趋势。因此，已有受保护 ECS/EIP/NAT 客户端访问某个 RDS 公网 IP 时，可以研究按目的/源 RDS 公网 IP 统计这条路径的请求和响应；**它不包含其他未经过这些边界的公网客户端访问**。[8]

把普通 RDS 改为经过自建公网代理/EIP 再访问内网 RDS，可以在可控代理处计数，但这是业务访问架构改造，会新增成本与可用性责任，不能当作给现有 RDS 增加一项只读 IAM 权限即可实现的方案。

## 建议的验证顺序

1. 先确认全部 RDS 私网访问方和现有 VPC 流日志/SLS 是否已开启；如已有日志，使用现有数据核验 IP、端口、ENI 和两个方向。
2. 对需要的 RDS 托管侧采集能力，向阿里云确认具体实例是否支持；不要仅根据“采集 VPC 所有 ENI”的通用描述作推断。
3. 若仅能采集客户端侧，明确展示为“已覆盖客户端至 RDS 的内网流量”，并记录覆盖范围。全部客户端覆盖、时间窗/口径验证通过前，不用残差替换 RDS 公网或内网告警。
4. 如新开通流日志，先评估生成费、SLS 费用和所需管理权限；运行时采集用户只保留资源发现、日志查询所需的只读权限。具体策略应按真实日志 Project/Logstore 和已选方案生成。
