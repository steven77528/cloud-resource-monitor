# 告警内容展示

适用于现有 **云业务与开发 · 问题看板**，UID `cloud-business-dev-v1`。
保留原来的五列：级别、账号、资源类型、资源名称、告警内容。

## 2026-10-20 网络告警显示不清

原告警表仅为余额、到期指标关联实际值，其他指标走不可用值分支。
`network_in_bps`、`network_out_bps` 没有中文映射，最终被统一显示成“其他监测内容”，
因此无法从一行告警判断具体指标或当前数值。

本次只修正同一看板的告警明细内容：

- 网络入站与出站分别显示，bit/s 转成十进制 Mbps；阿里云 ECS 标明内网，华为云 ECS 标明网卡合计，RDS 标明总网络口径。
- 华为云 ECS 告警使用“ECS 总网卡入站 / 出站”，图表标题也去掉括号中的范围说明；采集仍为所有网卡的公网与内网合计。
- 网络告警内容进一步简化为“RDS 出站：272.21 Mbps；达到 200 Mbps，持续 5 分钟”，末尾不追加“告警”二字。ECS 同样显示方向、当前值、阈值与持续时间，保留内网或总网卡口径。
- 阈值文案由网络配置中的规则 ID、P0/P1/P2 级别、比较符和持续时间生成，不按最近数值推算；相同阈值下，阿里云和华为云 ECS 使用各自的持续时间。缺少当前值时仍展示已配置的条件，未匹配的规则明确显示“阈值未提供”。
- 所有指标按完整任务和指标身份关联最近有效值，仅任务状态为 `ok` 且样本仍新鲜时展示。
- 旧样本过期、任务异常或没有当前值时，保留告警并明确显示数值不可用，不补零。
- 未知指标保留原始指标名称和值，不再统一替换成“其他监测内容”。
- 既有余额和到期文案、其他面板、变量、网络分区及独立时间控件保留。

告警表示引擎尚未解除的状态。最近值可能已下降，或正在等待恢复所需的连续正常样本；
不要将“存在未解除告警”解释为最近每一个采样点都仍超过阈值。
RDS 总网络吞吐可能包含复制等流量，不能还原 ECS 到 RDS 的通信关系，也不能据此认定带宽已满或数据库故障。
网络规则中的 200 Mbps 等是初始运维阈值，不是云实例的带宽上限。

本次无需构建镜像、替换采集服务、修改生产配置或更新通知网关。
看板直接查询现有 Prometheus 指标，不增加云 API 请求。

## 看板维护

`scripts/update_business_alert_details.py` 只更新此 UID 的 `panel-2`，不创建新看板。
先从线上「编辑 → 代码」复制当前 Grafana v2 JSON，再对导出文件运行脚本，
将输出应用到同一看板并保存。输入和输出分别指定，其他面板按导出内容保留。

```powershell
python scripts/update_business_alert_details.py --input grafana/cloud-business-dev-original.json --output grafana/cloud-business-dev-updated.json
```

维护脚本默认读取 `config/network-traffic.yaml`，也可用 `--network-config 实际网络配置路径`
指定与服务器一致的规则文件。当前 exporter 不导出规则阈值，因此这里是生成看板时的配置快照；
生产修改阈值、持续时间或规则绑定后，需使用实际配置重新生成并保存此表的映射，不能只改采集端。

不要用历史 `grafana/cloud-resource-monitor.json` 覆盖现有业务看板。
项目 `grafana/cloud-business-dev-v1.json` 同步保留本次告警内容修正，
若线上其他图表有后续编辑，应从线上最新导出生成更新，避免覆盖这些编辑。
