# 爱签套餐及账单接口官方文档核查

核查日期：2026-09-11。针对当前已确认使用 OpenAPI 的应用，核查能否直接查询套餐总量、剩余签署份数、商业有效期，以及能否取得官方账单。

## 结论

**官方公开文档可以确认存在 OpenAPI“昨日账单接口”，但本次核查仍不能确认存在可直接返回套餐总量、实时剩余份数或商业到期日期的公开查询接口。**

这比“没有找到套餐接口”多了一条可以落地调查的官方路径：`/partner/bill/yesterday` 返回接入商 T-1 账单的 Excel 文件。公开页没有公布 Excel 的列结构，也没有写明包含套餐余量或到期日期，因此不能把这个账单接口直接当作套餐余额查询接口。其数据范围写的是“接入商”，也不能直接推定为当前单个 OpenAPI 应用。

| 要确认的能力 | 官方文档能确认到的范围 | 对当前监控的含义 |
| --- | --- | --- |
| 昨日用量/账单文件 | 有，OpenAPI 提供 T-1 账单文件下载 | 可在权限及样本字段确认后开发自动账单采集 |
| 套餐总量、已用量、实时剩余量 | 所检查的公开文档未核实到对应查询字段 | 继续保留明确标为 `ledger` 的台账来源，不能伪造官方余额 |
| 套餐商业到期日期 | 所检查的公开文档未核实到对应查询字段 | 不能使用授权、合同或证书的有效期替代 |
| 当前应用是否已经开通账单权限 | 公开文档无法确认个别账号权限 | 需要现有业务后台信息或厂商确认，未调用真实接口验证 |

## 已确认：OpenAPI 昨日账单接口

来源：[官方“昨日账单接口”](https://web.asign.cn/platform/openDoc/docDetail?mid=billyesterday)。页面标示更新时间为 2025-01-07 20:00:00；核查时无需登录即可读取正文。

官方接口描述为：“获取接入商 T-1 账单详情，需开启账单推送权限”。地址：

```text
https://{host}/partner/bill/yesterday
```

请求参数说明为：“无请求参数，但需传空 json 字符串：`{}`”。没有公开的日期、应用 ID 或套餐 ID 查询参数。不能根据接口名称自行补充这些参数，也不能宣称它支持历史任意日期回补。

成功响应使用 `code=100000`，`data` 内公开字段如下：

| 字段 | 官方类型 | 官方含义 |
| --- | --- | --- |
| `fileName` | String | 文件名称，固定为 `用量信息.xlsx` |
| `md5` | String | 文件 MD5 值 |
| `fileType` | Integer | 文件类型，固定为 `2` |
| `size` | Long | 文件大小 |
| `base64Data` | String | 文件 Base64 |

页面列出以下错误码：

| 错误码 | 官方描述 |
| --- | --- |
| `101050` | 请接入者先联系商务开启账单推送权限 |
| `101051` | 请接入者先联系商务开启费用计价 |
| `101052` | 账单信息下载失败 |

正文明确要求账单推送权限，并列出了费用计价未开启的错误。公开说明不足以判断所有账单类型是否都必须同时开启费用计价，应由厂商确认适用条件。这里没有替用户开通权限，也没有发送商务消息。

**公开文档没有展示 Excel 列、行含义、金额单位、统计时区、生成时间、应用划分、重复生成规则或套餐有效期字段。** 即使文件中存在昨日消费量，也不能直接用“购买总量减累计消费量”宣称当前准确余量，除非已经核对续购、退还、过期、其他应用共同消耗及计费口径。

## 其他 OpenAPI 查询没有提供这些套餐字段

- [查询应用列表](https://web.asign.cn/platform/openDoc/docDetail?mid=queryApplication)：公开响应为分页信息，以及应用 `id`、`appId`、`appName`、`createTime`、`remark`、`platform`。其中 `total` 明确是“总应用数量”，不是套餐总量；`platform` 表示应用平台类型。
- [查询企业信息](https://web.asign.cn/platform/openDoc/docDetail?mid=getCompUser)：用于企业用户信息及实名认证状态；不能把认证状态、认证时间当作套餐剩余或商业到期。
- [OpenAPI 概述及接入指南](https://web.asign.cn/platform/openDoc/initialize)：能确认接入协议和环境，不是应用商业套餐状态的查询结果。

本次也检索了实际承载公开 OpenAPI 正文的官方静态文档资源，相关“剩余天数”“有效期”命中主要指合同签署期限、文件链接期限、证件或证书期限。没有将这些同名概念作为套餐字段。

## 核查范围和限制

本次只读取公开官方网页及网页实际加载的静态文档资源，没有登录账号、请求爱签业务 API、运行 SDK 示例、创建合同、发送通知或修改任何账号和任务开关。

公开文档资源取自 `https://web.asign.cn/platform/openDoc/initialize` 的当前网页脚本：

- [当前 OpenAPI 正文资源](https://web.asign.cn/static/js/57.0d6756bd88e1e6233b87.1788429699306.js)：核对账单正文并检索余额、套餐、资源包、剩余、账单、到期、有效期、费用、扣费相关内容。
- [当前共享目录及部分文档资源](https://web.asign.cn/static/js/0.f2bd292d20abd3a2a725.1788429699306.js)：核对 OpenAPI 目录和应用查询正文；该资源还含网站业务组件，未把后台组件中的套餐显示或内部调用视为正式对外 API。
- [当前站内文档搜索实现](https://web.asign.cn/static/js/165.ebf148d0235123f82a01.1788429699306.js)：搜索匹配目录条目的名称及 URL，并非所有文档正文的全文检索。

这些静态资源带版本哈希，后续发版后地址可能变化，用户阅读应优先使用上文稳定的文档页面链接。“昨日账单接口”在核查时有可直接访问的正文，但没有在已读取的共享目录数据中找到该 ID；这也说明站内搜索无结果或目录没有入口，不能单独证明官方不存在能力。

本次没有取得登录后文档、商务专属文档、当前应用权限清单或实际账单 Excel；未公开、需单独开通或账号专属的套餐查询能力仍有可能存在。结论严格限于已核实的公开文档，不应表述为“爱签没有套餐查询接口”。

## 后续落地需要确认的内容

对于现有 OpenAPI 接入，优先确认 `/partner/bill/yesterday` 的权限及一份脱敏 `用量信息.xlsx` 样本。需要核对它是接入商汇总还是含可区分应用/套餐的明细、列名和单位、生成时间及重复下载规则。只应按样本中真实存在且含义明确的字段开发采集。

如要完成套餐余量及商业到期的自动监控，还需厂商明确：是否存在对应套餐查询接口、正式文档和所需权限；或者上述官方账单是否提供套餐 ID、总量、剩余量、单位及有效期。得到这些证据前，项目继续使用明确标注 `ledger` 来源的台账，不把 T-1 用量、企业认证或合同状态混作实时套餐余额。
