# 华为 RDS 与阿里云网络监控复查

核查日期：2026-10-30。本文记录在华为 ECS 内网估算负差排查后，对华为 RDS 及阿里云 ECS/RDS 的追加只读审计。统一历史查询窗口为**北京时间 2026-10-29 15:20:00 至 2026-10-30 15:19:59**；“近七天邮件”是另一项告警记录查询，不等同于该 24 小时指标窗口。

本窗口内，华为三台 RDS 的 1,728 个双向五分钟估算差值均非负，未发现 ECS 已复现的“单个五分钟原始点减五个分钟点均值”采样结构。阿里云 ECS 使用原生内网指标、RDS 使用总吞吐指标，均不做总量减公网；20 条源序列未发现负数、非法值或冲突点。阿里云部分 ECS 历史分钟点存在缺口，但现有证据不能将其归为历史采集失败邮件的确定原因。

以上只表示**本窗口未发现相应问题**，不保证未来不会发生，也不能代替缺少原始日志的历史轮次诊断。

## 核查方式与边界

在 `192.168.120.28` 的原项目及现有容器中，独立执行只读云 API 查询和监控库只读事务，事务结束后 `rollback`。没有重启服务、启动额外调度器、写监控数据库、发送测试通知，或改变配置与采集算法。凭据仅在现有进程中使用，不输出配置原文、请求头或密钥。

复查脚本保存在本项目：

- [audit_rds_aliyun_network_20261030.sh](../work/audit_rds_aliyun_network_20261030.sh)：目标与口径、源序列、原始/聚合复算、当轮采集和近七天通知统计。
- [audit_network_failure_windows_20261030.sh](../work/audit_network_failure_windows_20261030.sh)：阿里云网络告警时间线及华为 `rds-PMS` 出站复核，补齐首轮工具输出显示长度限制所省略的方向记录。

脱敏数值汇总见 [network-scope-followup-20261030.json](../work/network-scope-followup-20261030.json)。两份探针的嵌入 Python 语法离线检查通过，远程执行均退出 `0`；本轮验证只读，不运行正式采集调度。

华为绑定核验读取当前同地域、同项目的 RDS 与 EIP 完整清单。当前映射成立，不等于已经证明整个历史 24 小时内绝无换绑。本文中的历史差分以查询时核实的当前映射复算，保留这一证据边界。

## 华为云 RDS

### 范围与源口径

任务为 `huawei-rds-network`，共三台 `Ha` 拓扑 MySQL：`rds-yj-pms`、`rds-PMS`、`rds-IOT`。每台均按当前公网地址唯一关联一个 EIP，覆盖该实例当前返回的全部公网地址，没有把共享带宽整体值分摊给实例。

| 来源 | 入站 | 出站 | 查询维度 | 现场原始单位 |
| --- | --- | --- | --- | --- |
| RDS 总网络 | `SYS.RDS/rds004_bytes_in` | `SYS.RDS/rds005_bytes_out` | `rds_cluster_id` | `byte/s`，乘 8 转为 `bit/s` |
| 关联 EIP 公网网络 | `SYS.VPC/downstream_bandwidth` | `SYS.VPC/upstream_bandwidth` | `publicip_id` | `bit/s`，不再换算 |

两个方向分别计算 `RDS 总速率 - 全部关联 EIP 同向公网速率之和`。没有在入站与出站之间相减，也没有将公网地址字符串用作 EIP UUID。

官方原始周期中，RDS 与 EIP 都是一分钟；RDS 仍统计所有网络适配器总吞吐，不是原生纯内网指标。此次只覆盖上述三台主备 MySQL，不外推到 PostgreSQL、集群/分布式实例或其他地域。当前估算实现支持的引擎、拓扑及测量边界见 [华为网络口径核对](huawei-network-scope-audit.md)。

### 原始序列与五分钟聚合复算

对每台实例的每个方向，以及相应 EIP，分别查询 `period=1/60/300`、`filter=average`，按实际返回单位转为 `bit/s` 后复算。

| 检查 | 实测结果 |
| --- | --- |
| RDS 原始值与一分钟值 | 每方向 `period=1`、`period=60` 序列完全一致，均为 1,440 点，单位全部 `byte/s` |
| EIP 原始值与一分钟值 | 每方向均有 1,440 点，单位全部 `bit/s` |
| 五分钟桶原始点数 | RDS 与 EIP 均为每桶 5 个分钟点，共 288 桶 |
| RDS API 五分钟值与原始均值 | 最大绝对差不超过 `0.06400001 bit/s` |
| EIP API 五分钟值与原始均值 | 最大绝对差不超过 `0.006 bit/s` |
| 同时间戳差分 | 六个方向共 `6 × 288 = 1,728` 个差值，负差 0，缺失公共桶 0 |

原始均值与 API 聚合的差异处于上述数值舍入范围。本窗口内没有观察到 ECS 那种 RDS 每桶单点、EIP 每桶五点的统计基础差异；这不能证明不同测量位置的速率在所有时刻都严格可比，也不构成固定平移时间戳的依据。

| 实例 | 入站最小估算差值，bit/s | 出站最小估算差值，bit/s |
| --- | ---: | ---: |
| `rds-yj-pms` | 2,595,069.73 | 79,434,980.32 |
| `rds-PMS` | 14,064,157.71 | 288,030,567.92 |
| `rds-IOT` | 141,408.24 | 350,914.16 |

### 健康状态与处理

近七天 `huawei-rds-network` 的 `collection-error` 邮件记录为 0。已上线的共享估算质量处理同样覆盖 RDS：若后续出现有限负差，按资源标记估算不可用；真实 API、字段、单位、非有限值、缺失/陈旧/不对齐数据和映射错误仍为采集错误。此次没有为 RDS 额外修改算法、源、周期或通知策略，恢复条件见 [估算可用性](network-traffic.md#估算可用性)。

## 阿里云 ECS

`aliyun-hycen` 的 ECS 网络任务显式选择零台实例，返回 `no_data`，属于清单配置的正常结果，不是采集故障。`aliyun-yuanzhu` 的 ECS 网络任务选择三台，使用原生 `IntranetInRate` / `IntranetOutRate`，`scope=intranet`，全部 `source_unit=bit/s`，不依赖 EIP 相减。

三台 ECS 的每个方向在历史窗口内分别取得 1,433、1,434、1,387 个点；各序列首点为 10 月 29 日 15:21，末点为 10 月 30 日 15:19。首点之前的 15:20 不计入“内部缺分钟”，三台每方向内部缺分钟分别为 6、5、52，最大相邻点间隔分别为 180、120、180 秒。没有负数、非法值或相同时间戳冲突值。

上述最大间隔数值低于任务配置的 300 秒最大源年龄，但历史相邻点间隔与某轮查询时的最新样本年龄不是同一概念。缺分钟本身不足以证明历史轮次发生了陈旧错误或接口超时。当轮三台均取得有效双向数据，共 6 点，结果 `ok`，最新源样本年龄 `5.605` 秒。

## 阿里云 RDS

两个账号分别有 2 台和 5 台 MySQL，共七台。源指标为 `MySQL_NetworkInNew` / `MySQL_NetworkOutNew`，`scope=all`，继续明确展示实例总网络吞吐；全部 `source_unit=bit/s`、`multiplier=1`，没有总量减公网计算。

返回的历史点内部均以 60 秒连续，相同时间戳未出现冲突，源值无负数或非法值。各资源当轮最新源年龄为 `125.605` 或 `185.605` 秒，同一资源入出站最新源时间差均为 0。两个账号当轮分别返回 4、10 个有效点，均为 `ok`。

阿里云三台 ECS 的 6 条源序列，加上七台 RDS 的 14 条源序列，共 20 条，均未发现负值、非法值或冲突点。由于 ECS 为原生内网、RDS 为总量口径，本次检查不代表已为阿里云 RDS 得到内网估算。

## 结论适用范围

此次未发现华为 RDS 在统一窗口内出现负差、缺失公共桶或 ECS 已复现的原始采样数量差异；阿里云网络源也未见负值、非法值或冲突。对阿里云历史采集失败邮件，已确认任务和时间分布，具体失败原因仍缺少对应轮次原始异常证据。

没有据此切换来源、平移时间、补零、修改阈值或关闭任何账号/任务/渠道。当前映射不追认历史绑定不变，本窗口正常不保证未来每个窗口正常。原 ECS 负差的原因与质量处理见 [专项核查](huawei-network-negative-difference-research.md)，原邮件排查见 [采集报错排查](troubleshooting-collection.md#2026-10-30-频繁采集失败邮件)。
